문제 정의

옷장엔 옷이 넘치는데,
아침마다 코디 고민은
왜 이렇게 길까요?

STICKER는 '옷이 없는' 문제가 아니라 '결정이 어려운' 문제를 풉니다. 매일 아침 날씨·일정·기분에 맞는 코디를 AI가 먼저 제안하고, 사용자는 고르기만 하면 됩니다.

1
옷장 디지털화의류 사진을 찍으면 Meshy AI가 2D 모델로 자동 변환
2
맥락 기반 추천날씨·일정·무드 슬롯으로 상황에 맞는 코디 생성
3
자연어 보정"오늘 면접 있어" 한마디로 코디·준비물까지 재조정
4
나만의 코디 저장드래그앤드롭으로 직접 조합하고 코디셋으로 보관
주요 기능

촬영 → 모델화 → 추천 → 보정 → 저장. 실제 서비스 화면으로 살펴보세요.

동작 원리

추천 한 번에 세 개의 서버가 움직입니다

앱의 요청은 Spring Boot를 거쳐 SQS 큐에 적재되고, FastAPI AI 서버가 비동기로 소비해 결과를 되돌려 줍니다.

App 요청날씨·일정·무드 슬롯과 옷장 데이터를 담아 추천 요청→
Spring Boot인증·검증 후 작업을 SQS 큐(일별추천·보정·결과)에 적재→
FastAPI AIFashionCLIP 임베딩 cohesion + 보온 산식으로 조합 스코어링→
🎨
이미지 생성마네킹 합성·투명 배경 후처리로 코디 프리뷰 생성→
결과 · 알림결과 큐를 BE가 소비·저장하고 FCM 푸시로 사용자에게 전달
시스템 아키텍처

세 개의 서버, 하나의 시스템

동기 API와 비동기 메시지 큐를 나눠, 무거운 AI 작업이 사용자 응답을 막지 않도록 설계했습니다.

추천 요청은 백엔드를 거쳐 SQS 큐에 쌓이고, AI 서버가 비동기로 꺼내 처리합니다. 덕분에 AI가 느려도 일반 API는 멈추지 않고, AI 서버만 독립적으로 확장할 수 있습니다.

관측성 — Prometheus 15초 스크랩 · app_operation_seconds 커스텀 메트릭 · p95 > 1.5s·5xx > 5% 알림 · 느린 쿼리 300ms 임계

기술 스택

프론트엔드 · 백엔드 · AI 서버를 독립 배포하고, AWS 인프라 위에서 비동기로 연결했습니다.
