추천 작업을 큐에 맡기고 백엔드는 손을 뗀다

풀어야 했던 문제무거운 AI 연산을 백엔드가 직접 떠안으면, 추천이 오래 걸릴 때 일반 API 요청까지 줄줄이 밀립니다.

추천·보정 작업을 SQS 큐에 적재하고 바로 응답한 뒤, AI 결과는 별도 결과 큐를 long-polling으로 소비합니다. 저장 로직의 순서 가정을 지키기 위해 결과 소비를 단일 가상 스레드로 돌리되, 20초 long-poll 동안 OS 스레드를 점유하지 않게 했습니다.

반복 조회 부하를 캐시로 덜어내기

풀어야 했던 문제옷장·코디 목록처럼 자주 열리는 화면이 매번 DB를 때리면 부하가 쌓입니다.

자주 조회되는 목록을 Redis에 짧게 캐싱해 DB 쿼리를 제거했습니다. 반면 S3 presigned 뷰 URL은 인스턴스 로컬 Caffeine에 캐싱했는데, URL에 AWS 타임스탬프 서명이 박혀 인스턴스 간 공유가 의미 없기 때문입니다.

운영 문제를 메트릭·알림으로 먼저 잡기

풀어야 했던 문제장애를 사용자 신고로 알게 되면 늦습니다. API·DB 상태를 상시 계측해 임계 초과를 자동으로 알려야 했습니다.

AOP로 계층별 실행 시간을 커스텀 메트릭(app_operation_seconds)으로 노출하고, Prometheus가 15초 간격으로 스크랩, Grafana 대시보드로 가시화합니다. p95 지연·5xx 비율·DB 커넥션 대기에 알림 규칙을 걸어 임계 초과 시 경보가 울립니다.
