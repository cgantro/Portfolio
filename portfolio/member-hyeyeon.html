Backend · 옷장 / 코디 / 추천 도메인

옷장·코디·추천 도메인의 백엔드 API를 폭넓게 맡았습니다. S3 직접 업로드 서비스, 조회 API, 상황 보정 처리, FCM 알림과 인증까지 — 사용자가 만지는 데이터 흐름 대부분의 서버 측을 설계했습니다.

Spring BootSpring Data JPAS3 PresignedFCMJWT · Kakao OAuth
1

큰 이미지를 서버 부담 없이 올리는 업로드 계약

풀어야 했던 문제용량 큰 옷 사진을 전부 서버로 받아 중계하면 서버가 업로드 트래픽만으로 병목이 됩니다.

백엔드는 이미지를 직접 받는 대신 presigned PUT URL만 발급하고, 실제 파일은 앱에서 S3로 직행합니다. content-type 화이트리스트·키 구조·만료로 업로드를 통제하고, 업로드 후 별도 등록 호출로 옷장 아이템과 연결합니다.

계약 · 수치

항목값비고
업로드presigned PUT · 5분 만료Content-Type 헤더만
키 구조users/{userId}/items/{itemId}/…소유자 스코프
검증image/jpeg·png·webp파일 30MB · 요청 35MB
등록POST /wardrobe/itemsS3 이벤트 미사용 · 클라 드리븐

실패 · 엣지 처리

!
서명 무결성Content-Type이 서명과 정확히 일치해야 하며, 그 외 헤더 추가 시 서명이 깨집니다.
!
고아 객체S3 이벤트가 아닌 클라 등록 호출에 의존하므로, 업로드만 하고 등록하지 않으면 미연결 객체가 남을 수 있습니다.
2

옷장 · 코디셋 · 추천 조회 API

풀어야 했던 문제앱의 거의 모든 화면이 데이터를 읽습니다. 옷장·코디셋·추천 결과를 일관된 형태로 안정적으로 내려줘야 했습니다.

옷장 목록·상세, 코디셋 목록·상세, 추천 코디 조회와 아이템 상세 조회 API를 설계·구현했습니다. 자주 조회되는 목록은 캐시와 맞물려 DB 부하를 줄입니다.

계약 · 수치

영역API비고
옷장목록 · 상세 조회WardrobeQuery
코디셋목록 · 상세 조회CodiSet
추천추천 코디 · 아이템 상세 조회DailyRecommendationQuery
3

상황 보정 — 중복 요청을 막는 처리

풀어야 했던 문제상황 보정은 비동기 작업이라, 같은 요청이 연달아 들어오면 중복 처리·중복 결과가 생길 수 있습니다.

보정 작업의 job 발행과 preview 결과 처리를 구현하면서, 동시·중복 요청에 락을 걸어 한 번만 처리되도록 했습니다. AI 서버와의 ENUM·DTO 양식도 통일해 큐 연동을 안정화했습니다.

실패 · 엣지 처리

🔒
중복 요청 락같은 보정 요청이 중복 처리되지 않도록 락으로 단일 처리를 보장합니다.
🤝
협업 — 보정 작업의 큐 발행/결과 수신은 백엔드(홍윤표)의 SQS 인프라, 실제 보정 스코어링·이미지는 AI 서버(문지영)와 맞물립니다.
4

알림 전송과 인증

풀어야 했던 문제추천 완료를 사용자에게 알리고, 모든 요청을 안전하게 인증해야 했습니다.

FCM 알림 전송 처리를 구현하고, JWT 토큰 발급과 카카오 소셜 로그인 연동을 담당했습니다.
