# RobotPal

## 프로젝트 개요

실물 JETANK의 주행과 로봇 팔 조작을 가상 환경에서 시험하는 시뮬레이터입니다. 가상 카메라 영상과 Python 영상 인식 모듈을 연결하고, 같은 제어 흐름을 실물 장비에도 적용했습니다.

## 주요 기능

- 가상 JETANK 주행, 로봇 팔·집게 조작과 카메라 영상 확인
- Python 영상 인식 결과를 이동체와 팔·집게 명령으로 연결
- TCP로 실물 JETANK의 상태를 확인하고 조작
- OpenGL 화면의 카메라 프레임을 JPEG로 압축해 전송

## 역할

4인 팀에서 스트리밍·통신·제어 연동을 맡았습니다. 카메라 프레임 압축과 TCP 송신을 분리했고, 실물 주행값에 맞춰 가상 이동 속도를 보정했습니다. 프로젝트 기간은 2025년 11~12월이며, 성능 비교는 2026년 10월 8일 기록입니다.

## 트러블슈팅

### JPEG 압축 때문에 시뮬레이션 갱신이 느려짐

영상 스트리밍을 켜면 시뮬레이션 갱신률이 102.38 FPS에서 66.70 FPS로 떨어졌습니다. GPU Readback이 원인이라고 보고 PBO를 적용했지만, 스트리밍 중 65.60 FPS로 개선되지 않았습니다. Tracy 측정에서 동기 Readback p50은 1.144ms, 메인 스레드 JPEG 압축 p50은 16.406ms여서 압축 작업을 메인 스레드 밖으로 옮겼습니다.

워커 4개가 JPEG 압축을 맡도록 바꾸고, 인코딩 대기열은 최대 6프레임을 보관하게 했습니다. 대기열이 차면 오래된 프레임을 버리고, TCP 송신 대기열도 최대 2프레임만 유지해 밀린 화면보다 최신 화면을 우선합니다.

```cpp title="RobotPal/src/Util/StreamingWorker.cpp · 인코딩 대기열"
{
    std::lock_guard<std::mutex> lk(m_encodeQueueMutex);
    if (m_encodeQueue.size() >= EncodeQueueCapacity)
        m_encodeQueue.pop();
    m_encodeQueue.push(std::move(job));
}
m_encodeQueueCv.notify_one();
```

## 결과

| 구성 | 스트리밍 중 시뮬레이션 | 카메라 송신률 | 스트리밍에 따른 갱신률 저하 |
| --- | ---: | ---: | ---: |
| 동기 Readback·JPEG | 66.70 FPS | 26.95 FPS | 34.84% |
| PBO·JPEG | 65.60 FPS | 25.49 FPS | 36.02% |
| PBO·워커 4개 | 96.01 FPS | 40.05 FPS | 6.74% |

동기 방식과 비교해 스트리밍 중 시뮬레이션 갱신률은 43.9%, 카메라 송신률은 48.6% 높아졌습니다. 1232×832 내장 GPU 환경에서 각 구성의 스트리밍 끔·켬을 5회씩 측정한 중앙값이며, 영상 수신과 압축 해제는 포함하지 않았습니다. 카메라 송신률은 목표 60 FPS에 도달하지 못했습니다.
