# 오토잉카 (AutoWing Car)

## 개요

공항 토잉카를 관제하는 6인 팀 프로젝트입니다. 서버 전반을 맡아 차량 장치, 데이터 저장, 관제 화면을 연결하는 흐름을 구현했습니다.

## 구현

차량 장치와는 MQTT로 명령과 상태를 주고받고, WebSocket 연결로 관제 화면에 차량 위치와 알림을 전달했습니다. 서버가 보낸 명령과 차량이 보고한 실제 주행 상태는 따로 관리해 명령 전달 여부가 차량 상태로 잘못 반영되지 않게 했습니다.

경로 탐색은 통제 구간과 다른 차량이 차지한 구간을 제외해 A*로 기본 경로를 찾고, Yen 알고리즘으로 우회 경로를 최대 세 개까지 계산했습니다. 연결선의 이동 시간을 경로 비용으로 사용하고, 차량에 전달할 때는 Ramer–Douglas–Peucker 방식으로 경로 모양에 영향이 적은 지점을 줄였습니다.

주행 이력과 지도 정보는 PostgreSQL에 저장하고 최신 차량 상태와 로그인 갱신 토큰은 Redis에서 관리했습니다.

## 문제 해결 과정

차량이 출입구에 도착했을 때 서버는 상태를 ‘도킹 완료’로 바꿨지만, 같은 주기에 처리한 차량 메시지가 이전 상태인 ‘출입구로 이동 중’을 다시 저장해 도착 처리가 반복됐습니다. 메시지 상태를 바로 저장하지 않고, 먼저 현재 데이터베이스 상태와 비교하도록 바꿨습니다. 자동 처리로 상태가 바뀌었다면 그 값을 유지하고, 바뀌지 않은 경우에만 차량에서 받은 상태를 저장했습니다.

또한 명령 저장 도중 차량에 메시지를 먼저 보내면 데이터베이스 작업이 취소돼도 장비 명령은 전달될 수 있었습니다. 명령 전송을 트랜잭션 확정 뒤로 옮겨 저장과 장비 동작의 순서를 맞췄습니다.
