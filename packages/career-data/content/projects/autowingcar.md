# 오토잉카 (AutoWing Car)

## 개요

공항 견인차 관제 서버를 개발한 6인 팀 프로젝트에서 백엔드 전반을 맡았습니다. MQTT 차량 통신, 경로 탐색, 데이터 저장과 WebSocket·STOMP 관제 화면 갱신을 구현했습니다.

## 구현

### 차량 통신과 관제 화면

차량 장치와 MQTT로 명령을 주고받고, 위치·속도·배터리·운행 상태와 명령 확인 응답을 처리했습니다. 명령이 전달됐다는 사실과 차량이 보고한 실제 상태를 분리해 저장했습니다.

WebSocket·STOMP로 차량·항공편·비상 알림의 변경 내용을 관제 화면에 보냈습니다. 차량 위치와 상태는 주행 이력으로 저장했습니다.

### 경로 계획

A*는 간선별 예상 이동 시간을 비용으로 사용해 기본 경로를 찾습니다. 통제 구간과 다른 차량이 점유한 지점·간선은 탐색에서 제외했습니다. Yen 알고리즘으로 대체 경로를 최대 3개 찾고, Ramer–Douglas–Peucker(RDP) 알고리즘으로 경로 형상을 유지하며 중간점을 줄였습니다.

### 저장과 배포

PostgreSQL에는 지도와 주행 이력을 저장하고, 개발·시험에는 H2를 사용했습니다. Redis는 최신 차량 상태와 만료 시간을 관리하는 로그인 갱신 토큰에 사용했습니다. JWT 요청 확인, Docker 실행 환경, GitLab CI 빌드·배포도 구성했습니다.

## 문제 해결 과정

차량이 출입구에 도착해 서버가 상태를 ‘도킹 완료’로 바꾼 직후, 이전 상태를 담은 메시지가 도착해 상태를 ‘출입구로 이동 중’으로 되돌리는 문제가 있었습니다. 수신값을 바로 저장하지 않고 기존 상태와 비교해, 서버가 확정한 상태 전이가 있으면 그 값을 유지하도록 바꿨습니다.

### 트랜잭션 커밋 뒤 명령 발행

DB 트랜잭션이 롤백돼도 먼저 발행한 MQTT 명령은 장비에 도착할 수 있었습니다. `afterCommit`을 적용해 DB 커밋이 성공한 뒤 MQTT 명령을 발행하도록 순서를 바꿨습니다. 이 처리는 커밋과 발행 순서를 정리하며, 장비의 명령 수행이나 네트워크 전송 성공까지 보장하지는 않습니다.
