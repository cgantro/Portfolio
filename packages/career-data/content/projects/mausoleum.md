# 영묘 (Mausoleum)

## 개요

언리얼 엔진 5 협동 게임에 음성 채팅을 구현한 6인 팀 프로젝트입니다. 저는 클라이언트의 마이크 캡처·Opus 처리·UDP 송수신·음성 재생과 별도 C++ 중계 서버, 게임 서버 네트워크 구조 개선을 맡았습니다.

## 게임 음성 처리와 수신 정책

`UPrivateVoiceChatComponent`가 음성 기능의 진입점입니다. 마이크 캡처, Opus 인코딩, UDP 송신, 화자별 디코딩과 재생을 각각의 구성요소로 나눴습니다. 인코더와 디코더 상태는 화자별로 유지해 여러 사람의 음성을 같은 코덱 상태에 섞지 않습니다.

음성 전달 정책도 게임 상태에 따라 바꿉니다. 로비에서는 `LobbyVoiceChatStrategy`가 방 참가자에게 음성을 전달하고, 게임에서는 `DistanceVoiceChatStrategy`가 거리 기반 음성 처리를 맡습니다. 3D 재생은 HRTF와 거리 감쇠를 사용합니다.

## UDP 중계와 룸별 작업 분배

C++ 음성 서버는 UDP 패킷의 길이와 종류를 확인하고, 세션 토큰·룸·화자 정보가 유효한지 검사한 뒤 룸 코드 해시로 입력 큐를 고릅니다. 같은 룸은 같은 큐와 워커가 처리하므로 여러 룸은 워커 풀에 나뉩니다. 이는 서버 내부의 작업 분배 방식이며, UDP에서 도착 순서가 바뀐 패킷을 복원하지는 않습니다.

```cpp title="룸별 음성 입력 큐 분배"
const size_t shard = shardIndexForRoom(roomCode);
if (shard >= voiceInboundQueues_.size()) {
    return;
}

VoiceInboundTask task;
task.packet = std::move(packet);
task.queuedAt = std::chrono::steady_clock::now();
voiceInboundQueues_[shard]->push(std::move(task));
```

패킷 데이터는 참가자마다 복사하는 대신 공유 소유권으로 전달해 애플리케이션 내부 복사를 줄였습니다. 네트워크 송신까지 복사가 없는 구조는 아닙니다. 네트워크 이벤트 루프와 소켓 수명 처리는 운영체제별 구현을 인터페이스 뒤로 분리했습니다.

## 창 포커스 전환 뒤 오래된 음성 처리

게임 창이 비활성화된 동안에도 캡처 데이터가 쌓여, 포커스를 되찾은 뒤 이전 음성이 늦게 전달될 수 있었습니다. 비활성화 시 캡처 버퍼를 비우고 Opus 인코더 상태를 초기화해, 복귀 후 오래된 입력을 이어 보내지 않도록 했습니다.

송신은 16kHz 단일 채널, 20ms 프레임, 24kbps로 설정했습니다. 이 설정은 구현한 인코더 구성값이며 음성 지연이나 패킷 손실 개선을 나타내는 측정치는 아닙니다.
