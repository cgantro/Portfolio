# 영묘 (Mausoleum)

## 프로젝트 개요

언리얼 엔진 5로 만든 6인 팀 협동 게임입니다. 게임 안에서 방과 거리에 따라 음성을 전달하고, 각 플레이어의 음성을 따로 재생하는 기능을 구현했습니다.

## 주요 기능

- 마이크 입력을 Opus로 압축해 UDP로 보내고, 수신 음성을 화자별로 복원·재생
- 로비에서는 방 참가자에게, 게임에서는 거리 정책에 따라 음성 전달
- C++ 음성 서버에서 패킷과 세션 정보를 확인하고 방 단위로 작업 분배
- 웹소켓 로비, 게임 진행 서버, 음성 서버를 연결하고 페이즈별 아이템 생성 처리

```cpp title="룸 코드 기준으로 음성 작업 큐 선택"
const size_t shard = shardIndexForRoom(roomCode);
if (shard >= voiceInboundQueues_.size()) {
    return;
}

VoiceInboundTask task;
task.packet = std::move(packet);
task.queuedAt = std::chrono::steady_clock::now();
voiceInboundQueues_[shard]->push(std::move(task));
```

## 역할

6인 팀에서 UE5 음성 클라이언트와 C++ UDP 음성 서버를 구현했습니다. 마이크 캡처부터 Opus 인코딩·송수신·재생까지 연결하고, 서버에서는 패킷 검사·룸별 작업 분배·음성 중계를 맡았습니다. Windows와 Linux의 네트워크 이벤트 처리는 운영체제별 구현으로 나눴습니다.

## 트러블슈팅

### 게임 창에 돌아오면 이전 음성이 늦게 재생됨

창이 비활성화된 동안에도 마이크 캡처 데이터가 쌓여, 다시 포커스를 얻은 뒤 오래된 음성이 전달됐습니다. 비활성화될 때 캡처 버퍼를 비우고 Opus 인코더 상태를 초기화하도록 바꿨습니다. 복귀 뒤에는 이전 입력을 이어 보내지 않고 새 음성부터 인코딩합니다.

송신은 16kHz 단일 채널, 20ms 프레임, 24kbps로 설정했습니다.

## 결과

로비 전체 전달과 게임 내 거리 기반 전달을 별도 정책으로 운영하고, 룸 코드 해시를 기준으로 같은 방의 패킷을 같은 작업 큐에 보냅니다. 여러 방은 워커 풀에서 나눠 처리하며, 여러 참가자에게 중계할 때는 패킷 데이터를 공유해 애플리케이션 내부 복사를 줄였습니다.
