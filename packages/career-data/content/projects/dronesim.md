# DroneSim

## 프로젝트 개요

사람이 지정한 시설물 외벽 위치까지 드론을 보내 EO 영상을 수집하는 비행 시뮬레이터입니다. 촬영 영상과 위치·시각·자세 기록을 함께 남겨 외벽 확인 임무를 시험합니다. 2026년 8월부터 개인 프로젝트로 개발 중이며, Flecs ECS·AirSim·UDP·JSON 시나리오를 사용합니다.

## 주요 기능

- 3D 지형과 OSM 건물을 보며 외벽 시험 위치와 비행 경로를 정합니다.
- 지정 위치까지 드론을 비행시키고 EO 영상을 촬영해 임무 기록과 함께 저장합니다.
- 게임패드·UDP 지상통제·JSON 시나리오로 같은 비행 명령을 입력합니다.
- 여러 드론에 임무를 나누고 상태 보고가 끊긴 기체의 미완료 임무를 다시 배정합니다.
- 웹 데모에서는 운동학 모델을, Windows 네이티브 실행에서는 AirSim 강체 물리를 사용합니다.

웹 화면의 지형과 건물은 시각화용이며 웹 데모의 운동학 모델은 강체 비행 성능을 재현하지 않습니다. 영상은 사람이 확인하며 파손 여부를 자동 판정하지 않습니다.

## 역할

개인 프로젝트에서 화면 갱신과 분리한 고정 주기 시뮬레이션 중심부를 구현하고, 드론 상태·비행 명령·충돌 처리를 연결했습니다. 게임패드·UDP·JSON 입력을 공통 명령으로 처리하고 네이티브 실행에 AirSim 물리를 연동했습니다. 외벽 촬영 임무의 영상과 기록 저장, 웹 영상 수신을 연결했으며 헤드리스 시나리오와 PX4 기록 재생으로 임무 흐름과 접촉 처리를 확인했습니다.

## 트러블슈팅

### 충돌 후보를 정렬하는 데 매 Tick 시간이 듦

충돌 후보를 찾기 전에 강체를 X 좌표순으로 매번 정렬하고 있었습니다. 위치를 갱신한 뒤 정렬 순서가 유지되는 경우에는 정렬을 생략하고, 순서가 바뀐 경우에만 다시 정렬하도록 바꿨습니다.

```cpp title="modules/simulation_core/src/PhysicsWorld.cpp"
for (auto& [positionX, bodyIndex] : bodyPositionsByX)
    positionX = bodies[bodyIndex]->collisionState.positionMeters.x;

if (!std::is_sorted(bodyPositionsByX.begin(), bodyPositionsByX.end()))
    std::sort(bodyPositionsByX.begin(), bodyPositionsByX.end());
```

Windows Release에서 준비 120 Tick 뒤 30,000 Tick을 조건별 3회 실행했습니다. 표는 반복별 p95의 중앙값이며, 물리 단계에는 좌표 갱신과 후보 쌍 검사도 포함합니다.

| 배치·기체 수 | 물리 단계 p95 개선 전 → 후 | 감소율 |
| --- | ---: | ---: |
| 분리·128대 | 188.0 → 184.2µs | 2.0% |
| 분리·256대 | 370.1 → 345.4µs | 6.7% |
| 분리·512대 | 741.8 → 669.9µs | 9.7% |
| 밀집·128대 | 472.3 → 408.6µs | 13.5% |
| 밀집·256대 | 827.6 → 791.6µs | 4.4% |

### PX4 기록 재생 중 접촉 판정이 반복마다 달라짐

PX4 공개 비행 기록을 재생할 때 접촉 위치가 `float` 반올림 경계에 걸리면 바닥 접촉 여부가 실행마다 달라졌습니다. 접촉 위치 비교에 좌표 크기를 고려한 허용 오차를 적용해 경계값에서 판정이 흔들리지 않도록 수정했습니다.

수정 뒤 새 프로세스로 12회 재생했을 때 상태 항목 간 차이는 각 항목의 원래 단위로 비교해 2.6×10⁻⁶ 이내였습니다. 이는 접촉 처리의 반복 안정성을 확인한 값이며, 비행 모델 정확도나 실기체 성능을 검증한 결과는 아닙니다.

## 결과

상태 보고 단절을 재현한 지정 시나리오에서 4~256대 조건별 3회 모두 완료율 100%를 기록했습니다. 단절 입력은 합성 시나리오로 재현했습니다.
