# DroneSim

## 프로젝트 개요

시설물 외벽을 확인할 위치까지 드론을 보내 EO 영상을 수집하는 비행 시뮬레이터입니다. 사람이 OSM 건물의 시험 위치를 고르고, 촬영 영상과 위치·시각·자세 기록을 확인하는 흐름을 구현하고 있습니다.

## 주요 기능

- 건물 외벽 시험 위치를 선택하고 촬영 지점까지 비행
- UDP 지상통제, 게임패드, JSON 시나리오 입력을 공통 비행 명령으로 처리
- 고정 주기로 기체와 카메라 상태를 갱신하고, 임무별 영상과 기록 저장
- 네이티브 빌드는 AirSim 강체 물리, 웹 데모는 운동학 모델로 동작
- 헤드리스 시나리오에서 여러 드론의 상태 보고와 임무 배정을 시험

웹 데모는 지형과 건물을 화면에 그리지만 충돌 계산에는 포함하지 않습니다. 외벽 영상은 사람이 확인하며, 파손 여부를 자동 판정하지 않습니다.

## 역할

개인 프로젝트로 시뮬레이션 중심부와 지상통제 입력을 구현했습니다. 화면 입력·게임패드·UDP·JSON을 공통 명령으로 연결하고, 네이티브 비행에는 AirSim을, 웹 데모에는 운동학 모델을 적용했습니다. 여러 기체 임무와 충돌 계산도 헤드리스 시나리오로 시험했습니다.

## 트러블슈팅

### 상태 보고가 끊긴 기체의 임무가 멈춤

하트비트 제한 시간을 넘긴 기체를 `unknown` 상태로 바꾸고, 맡은 임무를 대기열로 돌리도록 했습니다. 조정기는 연결된 기체 가운데 목표에 가까운 기체를 골라 미완료 임무를 다시 배정합니다. 기존 임무를 먼저 대기열에 반환해 재배정 중 임무가 중복되지 않게 처리했습니다.

### 충돌 후보 정렬에 매 Tick 시간이 듦

충돌 후보를 찾기 전에 강체를 X 좌표순으로 정렬하고 있었습니다. 위치를 갱신한 뒤에도 정렬 순서가 유지되면 정렬을 건너뛰고, 순서가 바뀐 경우에만 다시 정렬하도록 바꿨습니다.

```cpp title="modules/simulation_core/src/PhysicsWorld.cpp"
for (auto& [positionX, bodyIndex] : bodyPositionsByX)
    positionX = bodies[bodyIndex]->collisionState.positionMeters.x;

if (!std::is_sorted(bodyPositionsByX.begin(), bodyPositionsByX.end()))
    std::sort(bodyPositionsByX.begin(), bodyPositionsByX.end());
```

## 결과

헤드리스 모의 시나리오에서는 전체 기체의 25%가 상태 보고를 끊는 조건으로 임무를 재배정했습니다. 4~256대, 기체 수별 3회 실행에서 지정 시나리오 완료율은 모두 100%였습니다.

| 배치·기체 수 | 물리 단계 p95 개선 전 → 후 | 감소율 |
| --- | ---: | ---: |
| 분리·128대 | 188.0 → 184.2µs | 2.0% |
| 분리·256대 | 370.1 → 345.4µs | 6.7% |
| 분리·512대 | 741.8 → 669.9µs | 9.7% |
| 밀집·128대 | 472.3 → 408.6µs | 13.5% |
| 밀집·256대 | 827.6 → 791.6µs | 4.4% |

충돌 측정은 Windows Release에서 조건별 120 Tick 준비 후 30,000 Tick씩 3회 실행한 p95 중앙값입니다. 물리 단계에는 좌표 갱신과 후보 쌍 검사도 들어갑니다.

PX4 공개 기록 재생에서는 접촉 판정의 `float` 반올림 문제를 고쳤습니다. 수정 뒤 새 프로세스에서 12회 실행한 상태 항목 차이는 각 항목의 원래 단위로 비교해 2.6×10⁻⁶ 이내였습니다. 이 결과는 접촉 처리의 반복 안정성을 확인한 것이며 비행 모델의 정확도를 뜻하지 않습니다.
