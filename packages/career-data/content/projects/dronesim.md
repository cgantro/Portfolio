# DroneSim

## 프로젝트 개요

시설물 외벽을 살펴볼 드론 비행과 EO 영상 수집, 지상통제 흐름을 시험하는 시뮬레이터입니다. 사람이 정한 외벽 시험 위치를 비행해 촬영하고, 영상과 위치·시각·자세 기록을 함께 남깁니다. 2026년 8월부터 개인 프로젝트로 개발하고 있으며 Flecs ECS·AirSim·UDP·JSON 시나리오를 사용합니다.

## 주요 기능

- 탄천교 주변의 30m 격자 지형과 OSM 건물 정보를 보며 외벽 시험 위치와 비행 경로를 정합니다. 지형 정사영상 질감은 아직 적용하지 않았습니다.
- 게임패드, UDP 지상통제, JSON 시나리오에서 비행 명령을 보내고 드론 상태를 확인합니다. Windows 네이티브는 AirSim 강체 물리를, 웹 데모는 운동학 모델을 사용합니다.
- 지정한 위치에서 EO 영상을 촬영하고 위치·시각·자세 기록과 함께 저장합니다. 네이티브는 MP4·JSONL, 웹은 WebM·PNG·JSON 기록을 만듭니다.
- 네이티브 시뮬레이터와 지상통제 프로그램 사이에서 H.264/RTP 영상을 주고받고, 녹화 영상과 촬영 기록 파일도 전달합니다. 실시간 영상과 저장 파일은 서로 다른 전송 경로를 사용합니다.
- 여러 드론에 임무를 나누고 상태 보고가 끊긴 기체의 미완료 임무를 지정 시나리오에서 다시 배정합니다.

## 담당 역할

화면 갱신과 분리된 60Hz 고정 주기 시뮬레이션 중심부를 Flecs ECS로 구성했습니다. 게임패드·UDP·JSON 입력을 공통 비행 명령으로 연결하고, 네이티브 실행의 AirSim 강체 물리와 웹 실행의 운동학 모델을 구분했습니다.

EO 카메라 프레임을 수집해 촬영 정보와 함께 기록하고, 네이티브 H.264/RTP 송수신과 녹화 파일 전달을 지상통제 프로그램에 연결했습니다. 웹 실행에서는 WebM·PNG·JSON 자료 저장과 지상통제 화면의 내려받기를 구현했습니다.

## 트러블슈팅

### 충돌 후보 정렬을 매 Tick 다시 수행함

충돌 후보를 찾기 전 강체 목록을 X 좌표순으로 매 Tick 정렬했습니다. 위치를 갱신한 뒤에도 순서가 유지되는 경우가 있어 정렬 상태를 확인하고, 순서가 바뀐 경우에만 다시 정렬하도록 바꿨습니다.

```cpp title="modules/simulation_core/src/PhysicsWorld.cpp · 충돌 후보 순서 재사용"
for (auto& [positionX, bodyIndex] : bodyPositionsByX)
    positionX = bodies[bodyIndex]->collisionState.positionMeters.x;

if (!std::is_sorted(bodyPositionsByX.begin(), bodyPositionsByX.end()))
    std::sort(bodyPositionsByX.begin(), bodyPositionsByX.end());
```

Windows Release에서 준비 120 Tick 뒤 30,000 Tick을 조건별 3회 실행했습니다. 표는 반복별 물리 단계 p95의 중앙값이며, 물리 단계에는 좌표 갱신과 후보 쌍 검사도 포함합니다.

| 배치·기체 수 | 물리 단계 p95 개선 전 → 후 | 감소율 |
| --- | ---: | ---: |
| 분리·128대 | 188.0 → 184.2µs | 2.0% |
| 분리·256대 | 370.1 → 345.4µs | 6.7% |
| 분리·512대 | 741.8 → 669.9µs | 9.7% |
| 밀집·128대 | 472.3 → 408.6µs | 13.5% |
| 밀집·256대 | 827.6 → 791.6µs | 4.4% |

### PX4 기록 재생 때 접촉 판정이 반복마다 달라짐

PX4 공개 비행 기록을 재생하던 중 접촉 위치가 `float` 반올림 경계에 걸려 바닥 접촉 판정이 실행마다 달라졌습니다. 좌표 크기에 따라 달라지는 허용 오차를 접촉 위치 비교에 적용해 경계값의 판정이 흔들리지 않게 수정했습니다.

수정 뒤 새 프로세스에서 12회 재생했을 때 상태 항목 간 차이는 각 항목의 원래 단위로 비교해 2.6×10⁻⁶ 이내였습니다. 이는 접촉 처리의 반복 안정성을 확인한 값이며 비행 모델 정확도나 실기체 성능을 검증한 결과는 아닙니다.

## 결과

- 충돌 후보 정렬을 재사용한 뒤 분리·밀집 배치의 5개 측정 조건에서 물리 단계 p95가 2.0~13.5% 줄었습니다. Windows Release, 준비 120 Tick 후 30,000 Tick씩 3회 실행한 반복별 p95 중앙값입니다.
- 상태 보고 단절을 합성 입력으로 재현한 헤드리스 다중 드론 시나리오에서 4~256대 조건별 3회 모두 완료율 100%를 기록했습니다. 실제 UDP 장애나 실기체 임무 성공률은 아닙니다.
- Windows Release 로컬 왕복 시험에서 네이티브 H.264/RTP 영상의 인코딩·전송·디코딩을 확인했습니다. 다른 PC 사이의 전송은 확인하지 않았습니다.
- 자동 시험에서 네이티브 녹화 파일·촬영 기록 전달과 파일별 CRC-32 대조를 확인했습니다. 두 프로그램 창을 직접 연결하는 수동 시험은 남아 있습니다. 웹에서는 Chromium 검사로 내려받은 자료의 크기와 SHA-256을 확인했습니다.
