# Portfolio Codex guidelines
Read only the skill relevant to the active task in .agents/skills/. Setup instructions are in docs/CODEX_SKILLS_SETUP.md.

Source-of-truth: real source code, project logs, benchmark records, and user-confirmed career experience. Never invent roles, timelines, measured values, technical methods, or results. Keep measured/proven facts separate from plans, hypotheses, and intended implementations. Preserve benchmark conditions, units and uncertainty. Avoid putting private career data, credentials, or contact details into public Git history.

For Korean resumes and cover letters, use a professional connected technical register. Avoid rewriting all complex Korean sentences into short colloquial fragments. Preserve user-approved voice. For new text, emphasize verified judgment, implementation, technical trade-offs and relevance to the targeted role, without pretending to have executed unverified alternatives.

For portfolio work, use real product screenshots and code; verify GraspLink WebAssembly/SharedArrayBuffer and COI worker behavior before changing embedding. Do not break GitHub Pages routing or production deployment. Use Playwright screenshot evidence for design findings, separate subjective taste from reproducible defects. Local LLM and required remote MCP dependencies are excluded.

Subagents are optional and should be used only for independent reviews where useful. Reviewers must report verification limits and avoid fabricated scores.
