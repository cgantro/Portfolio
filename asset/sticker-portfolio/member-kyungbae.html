Frontend 리드 · Meshy/SSE 풀스택

프론트엔드 리드로서 옷장의 핵심 인터랙션을 맡았습니다. Meshy 2D 모델화 연동을 프론트와 서버 양쪽에서 구현하고, 드래그앤드롭 코디 메이커와 음성 기반 상황 보정 UX를 만들었습니다.

1

변환 완료를 묻지 않고 받는 실시간 수신

풀어야 했던 문제Meshy의 2D 모델화는 수십 초가 걸립니다. 앱이 "다 됐나?"를 반복 질의하면 낭비가 크고 사용자는 멍하니 기다려야 합니다.

앱은 변환을 요청한 직후 SSE로 서버와 연결을 한 번 열어두고, 완료 이벤트를 push 받습니다. 서버측은 백그라운드 가상 스레드가 Meshy의 완료 스트림을 대신 지켜보다가 끝나면 후처리·S3 업로드 후 앱의 SSE 연결로 결과를 밀어줍니다. 프론트(react-native-sse)와 서버(SseEmitter) 양쪽을 직접 구현했습니다.

2

끊김 없이 끌고 키우는 코디 메이커

풀어야 했던 문제옷을 직접 끌어다 코디를 짜는 화면에서, 손가락 조작이 버벅이면 금세 흥미를 잃습니다.

옷장 그리드에서 캔버스로 끌어오는 드래그와, 캔버스 안에서 옮기고(Pan) 키우고(Pinch) 고르는(Tap) 멀티터치 조작을 분리해 구현했습니다. 위치·스케일 갱신은 reanimated로 처리해 JS 스레드 부하 없이 부드럽게 따라옵니다.

3

"스티커야" — 음성으로 거는 상황 보정

풀어야 했던 문제그날의 사정은 버튼으로 다 담을 수 없습니다. 말로 던진 맥락을 받아 코디 보정으로 연결해야 했습니다.

호출어 "스티커야"를 평소엔 가볍게 엿듣다가, 감지되면 비연속 모드로 전환해 명령 문장을 받아 적습니다. 받은 텍스트는 상황 보정 엔드포인트로 보내 AI가 코디·준비물 팁을 돌려줍니다. 클라 훅과 서버 엔드포인트를 함께 구현했습니다.

옷장 스크롤을 가볍게 — 이미지 캐싱·프리페치

풀어야 했던 문제옷장은 이미지가 많아, 매번 원격에서 받아 그리면 스크롤이 무겁고 깜빡입니다.

이미지를 메모리·디스크 2단 캐시로 재사용하고, 홈 진입 시 옷장 데이터를 백그라운드에서 미리 불러옵니다(프리페치). 중복 요청은 진행 중 프로미스로 한 번만 나가게 묶었습니다.
