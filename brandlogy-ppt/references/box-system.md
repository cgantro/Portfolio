# Box System — 7가지 분할 패턴

Box System은 본문 영역(`x=0.422, y=2.20, w=12.49, h=3.85`)을 메시지 구조에
맞게 분할하는 좌표 시스템입니다. 모든 분할 박스는 동일한 fill·line·
rectRadius·shadow를 공유해 시각적 일관성을 유지합니다.

## 왜 Box System인가

v10 이전에는 본문 영역을 박스 없이 풀어놓았는데, 두 가지 문제가 생겼습니다.

1. **본문 영역 경계가 모호** — 콘텐츠가 어디서 시작해서 어디서 끝나는지 시각적 선언이 없으니 SO WHAT·Bottom Strip과 충돌
2. **카드 정렬의 기준 부재** — 카드마다 좌표가 흩어지면서 슬라이드 간 리듬이 깨짐

v11 Box System은 이 두 문제를 동시에 해결합니다. 단일 박스든 분할 박스든
**같은 styling을 공유**한다는 게 핵심 — 박스가 1개일 때와 7개일 때가
시각적으로 한 가족처럼 보여야 합니다.

## 공통 Styling (모든 패턴)

```javascript
fill: white                        // FFFFFF
line: containerLine (EDEEF0) 1pt   // 옅은 회색 라인
rectRadius: 0.18 (큰 박스)         // h ≥ 2.5
            0.14 (작은 박스 = 4분할 셀)  // h < 2.5
shadow: {
  type: "outer", color: "000000",
  blur: 12, offset: 2, angle: 90,
  opacity: 0.05                    // 매우 약함 — 자세히 봐야 보일 정도
}
```

박스 사이 표준 gap:
- 가로 gap (h-gap): **0.20"**
- 세로 gap (v-gap): **0.15"**
- 가로 gap이 세로보다 약간 큰 것은 광학적 균형 — 사람 시각이 수평 간격을 좁게 인지하는 경향 보정

박스 안 콘텐츠 padding (사방): **0.20"**

## Pattern 1 — Single Container (단일 박스)

```
좌표:
  Box: x=0.422  y=2.20  w=12.49  h=3.85

콘텐츠 가용 영역 (padding 차감):
  x=0.622 ~ 12.712  (w=12.09)
  y=2.40  ~ 6.05   (h=3.65)
```

**언제 쓰는가**
- 풀폭 시각화 1개 (Bar/Line/Heatmap/Pyramid + 우측 메시지/풀폭 다이어그램)
- 시각화 자체가 메시지를 다 전달할 때
- 데이터 밀도가 높아 분할하면 답답해질 때

**메시지 예시**
- "5개국 시장 규모 비교" → 가로 Bar chart 풀폭
- "디지털 전환 7단계 프로세스" → 풀폭 Flowchart
- "조직 구조 5단계" → 풀폭 Org Chart

## Pattern 2L — Vertical Split 2 (좌우 1:1)

```
좌표 (h-gap 0.20):
  L: x=0.422  y=2.20  w=6.145  h=3.85
  R: x=6.767  y=2.20  w=6.145  h=3.85

L 콘텐츠 가용: x=0.622 ~ 6.367  (w=5.745)
R 콘텐츠 가용: x=6.967 ~ 12.712 (w=5.745)
```

**언제 쓰는가**
- 두 개념을 동등하게 대비/비교
- 차트 + 인사이트 카드를 1:1 비중으로
- Before/After 좌우 배치

**메시지 예시**
- "자사 vs 경쟁사 4축 비교" → 좌 Slope, 우 해석 카드
- "Before 2020 → After 2025" → 좌우 Slope 또는 Bar
- "Problem 좌 / Solution 우" → 좌우 텍스트 + 아이콘

**주의**
- 좌우 콘텐츠 시각적 무게가 한쪽으로 쏠리면 비대칭(P5/P6)으로 교체
- 한쪽이 부속 정보면 비대칭이 더 자연스러움

---

## Pattern 2H — Horizontal Split 2 (상하 1:1)

```
좌표 (v-gap 0.15):
  T: x=0.422  y=2.20  w=12.49  h=1.85
  B: x=0.422  y=4.20  w=12.49  h=1.85

T 콘텐츠 가용: y=2.40 ~ 3.85 (h=1.45)
B 콘텐츠 가용: y=4.40 ~ 5.85 (h=1.45)
```

**언제 쓰는가**
- 데이터 시각화 위 + 인사이트 행 아래
- KPI strip 위 + Takeaway 카드 아래
- 시간축 위 + 세부 단계 아래

**메시지 예시**
- "KPI 4개 (상) + Takeaway 3개 (하)" → 상단 KPI strip, 하단 인사이트
- "Customer Journey (상 단계 + 하 감정)" → Journey Map 표준 레이아웃
- "Timeline (상) + 핵심 사건 카드 (하)"

**주의**
- T 영역 h=1.45는 차트 넣기엔 약간 좁음 — KPI/Strip/Step 카드용
- 둘 다 카드면 T는 강조용 1행, B는 디테일 3~4 카드 권장

## Pattern 3 — Vertical Split 3 (3분할 1:1:1)

```
좌표 (h-gap 0.18):
  L: x=0.422  y=2.20  w=4.043  h=3.85
  M: x=4.645  y=2.20  w=4.043  h=3.85
  R: x=8.868  y=2.20  w=4.043  h=3.85

각 박스 콘텐츠 가용: w=3.643
```

**언제 쓰는가**
- 3가지 동등 카테고리
- 3 페르소나 비교
- 3 옵션 / 3 솔루션 비교
- 과거-현재-미래 시점 비교

**메시지 예시**
- "타겟 페르소나 3명 비교" → Persona Card 3개
- "솔루션 A/B/C 장단점" → 각 박스에 라벨+빅 넘버+desc
- "Phase 1 / Phase 2 / Phase 3" → 단계별 핵심 + KPI

**주의**
- 박스 폭이 좁아서(4.043) 차트 넣기엔 부적합 — 텍스트/숫자/짧은 리스트 중심
- 한 박스만 강조하려면 `card({emphasis: true})` — 1개만

## Pattern 4 — Quadrant Split (2x2)

```
좌표 (h-gap 0.20, v-gap 0.15):
  TL: x=0.422  y=2.20  w=6.145  h=1.85
  TR: x=6.767  y=2.20  w=6.145  h=1.85
  BL: x=0.422  y=4.20  w=6.145  h=1.85
  BR: x=6.767  y=4.20  w=6.145  h=1.85

각 박스 콘텐츠 가용: w=5.745, h=1.45
rectRadius: 0.14 (작은 박스 기준)
```

**언제 쓰는가**
- 4가지 동등 항목 (4 트렌드, 4 가치, 4 분기)
- Eisenhower / Impact-Effort 같은 우선순위 4 사분면
- 4 단계 프로세스 (단, 흐름이 있으면 Flowchart 권장)

**메시지 예시**
- "MZ 소비 4축" → 각 박스에 축 이름 + 빅 넘버
- "긴급-중요 4 사분면" → Eisenhower 그대로
- "Q1/Q2/Q3/Q4 결과" → 분기별 KPI 카드

**주의**
- 2x2 Matrix(SWOT, BCG 등)는 별도 시각화 — Box Pattern 4가 아니라 P1 안에 직접 그리는 게 더 적합 (라인·색상 사용 다름)
- SWOT은 §15-G 컬러 레시피 참조

## Pattern 5 — Asymmetric 5:7 (좌소 우대)

```
좌표 (h-gap 0.20):
  L: x=0.422  y=2.20  w=4.95  h=3.85
  R: x=5.572  y=2.20  w=7.34  h=3.85

비율: 5/12 vs 7/12 컬럼 (황금비에 가까움)

L 콘텐츠 가용: w=4.55
R 콘텐츠 가용: w=6.94
```

**언제 쓰는가**
- 좌측 KEY MESSAGE / 빅 넘버 + 우측 본 시각화
- 좌측 핵심 요약 + 우측 디테일 차트
- 황금비에 가까운 비대칭 — 가장 자주 쓰는 비대칭 패턴

**메시지 예시**
- "좌: '13X' 빅 넘버 + 한 줄 / 우: Slope chart" → 임팩트 + 근거
- "좌: 한 줄 KEY MESSAGE / 우: Bar chart" → McKinsey 표준 레이아웃
- "좌: 단일 KPI + 설명 / 우: 시계열 Line"

**주의**
- 좌측에 시각화, 우측에 메시지는 어색함 — 시선이 좌→우로 흐르므로 결론(메시지)이 좌측에 와야 자연스러움

---

## Pattern 6 — Asymmetric 7:5 (좌대 우소)

```
좌표 (h-gap 0.20):
  L: x=0.422  y=2.20  w=7.34  h=3.85
  R: x=7.962  y=2.20  w=4.95  h=3.85

L 콘텐츠 가용: w=6.94
R 콘텐츠 가용: w=4.55
```

**언제 쓰는가**
- 좌측 본 시각화 + 우측 인사이트 카드 2~3개
- 좌측 메인 차트 + 우측 데이터 해석
- Positioning Map 등 큰 차트가 메인일 때

**메시지 예시**
- "좌: Positioning Map / 우: 자사 강점 3개 카드"
- "좌: Customer Journey / 우: 핵심 페인 포인트 3개"
- "좌: 큰 Heatmap / 우: 인사이트 3 행"

**주의**
- P5(5:7)와 P6(7:5)는 메시지 흐름이 반대 — 잘못 고르면 시선이 꼬임
- 메시지 먼저 보여줄지(P5), 데이터 먼저 보여줄지(P6) 결정

---

## Pattern 7 — Mixed Grid (혼합)

```
좌표 예 (좌 큰 박스 + 우 상하 2개):
  L:  x=0.422  y=2.20  w=7.34  h=3.85
  TR: x=7.962  y=2.20  w=4.95  h=1.85
  BR: x=7.962  y=4.20  w=4.95  h=1.85

TR/BR rectRadius: 0.14 (작은 박스)
```

**언제 쓰는가**
- 좌측 메인 시각화 + 우측 보조 정보 2개 (서로 독립된 카테고리)
- Bento Dashboard 톤 (애플 분석 화면 풍)
- 좌 메인 차트 + 우 상단 KPI + 우 하단 인사이트

**메시지 예시**
- "좌: Sankey 흐름도 / 우상: 총 트래픽 KPI / 우하: 전환율 KPI"
- "좌: 시계열 Line / 우상: 핵심 사건 / 우하: 향후 전망"
- "좌: Supply Chain Map / 우상: 비용 KPI / 우하: 리드타임 KPI"

**변형**
- 우 큰 박스 + 좌 상하 (대칭 반대) — 같은 styling, 좌표만 미러
- 상 큰 박스 + 하 좌우 — h 기준 분할도 가능

**주의**
- 3개 박스가 각각 다른 카테고리여야 함 — 같은 카테고리면 P3/P4가 더 적합
- 우측 두 박스는 KPI/짧은 카드만, 차트는 부적합 (너무 작음)

## 패턴 선택 트리

메시지 구조부터 시작해서 위에서 아래로 내려가며 매칭하세요.

```
메시지가 1개 풀폭 시각화로 끝나는가?
  YES → P1
  NO ↓

두 개념을 1:1로 비교하는가?
  YES → P2L
  NO ↓

데이터 + 인사이트로 분리되는가?
  YES → P2H (위 데이터, 아래 인사이트)
        또는 P5 (좌 메시지, 우 차트)
        또는 P6 (좌 차트, 우 인사이트)
  NO ↓

3가지 동등 항목인가?
  YES → P3
  NO ↓

4가지 동등 항목인가?
  YES → P4
  NO ↓

메인 시각화 + 보조 정보 2~3개인가?
  YES → P7
  NO ↓

여기까지 왔으면 메시지가 모호한 신호 → Ghost Deck로 돌아가서 재정의
```

## 패턴별 자주 하는 실수

| 실수 | 증상 | 해결 |
|---|---|---|
| P1에 정보 과다 | 풀폭 박스 안에 카드 6개+ | P4 또는 P7로 분할 |
| P2L 양쪽 무게 쏠림 | 한쪽이 비어 보임 | P5/P6 비대칭으로 교체 |
| P3에 차트 넣음 | 박스 폭 좁아 답답 | 텍스트/KPI만, 차트는 P5/P6 |
| P4를 SWOT으로 오해 | 4 박스 색이 제각각 | SWOT은 P1 안에 직접 (§15-G) |
| P5/P6 시선 흐름 역행 | 메시지 우, 차트 좌 | 결론 좌측 원칙 (P5) |
| P7 박스 3개 같은 카테고리 | P3과 시각적 동일 | 3개 박스는 독립 카테고리여야 |

## 코드 호출 패턴

```javascript
const H = require("./scripts/build-helpers");
H.initLayout(pres);

// Pattern 5 슬라이드 생성 (5:7 비대칭)
const s = H.bodySlide5(pres);

// 헤더
H.addHeader(s, "CHAPTER 02", "MZ는 가격이 아니라 '서사'에 지갑을 연다", "Sub explanation");

// 좌측 박스 (KEY MESSAGE 영역): x=0.422 w=4.95
// 콘텐츠 padding 0.20 적용 → 사용 가능: x=0.622 w=4.55
s.addText("13X", {
  x: 0.622, y: 2.80, w: 4.55, h: 1.5,
  fontFace: H.FONT, fontSize: 96, bold: true,
  color: H.C.brandDeep, charSpacing: -3, valign: "middle",
});

// 우측 박스 (차트 영역): x=5.572 w=7.34
// 콘텐츠 padding 0.20 적용 → 사용 가능: x=5.772 w=6.94
s.addChart(pres.ChartType.bar, data, {
  x: 5.772, y: 2.40, w: 6.94, h: 3.45,
  ...H.chartOpts({ chartColors: [H.C.brand] }),
});

// SO WHAT
H.addSoWhat(s, pres, "스토리텔링이 결국 객단가를 만듭니다.");

// Bottom Strip
H.addBottomStrip(s, 5, "Source: 페이퍼로지 자체 조사 2026");
```
