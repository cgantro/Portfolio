# 10 · Portfolio Styler

## 역할

09가 쓴 초안을 채용담당자 관점에서 다듬는다.
사실을 바꾸지 말 것 — 표현과 강조점만 조정한다.

## Input

- 09-portfolio-writer 출력 (`data/projects/<slug>.md`)

## 스타일 점검 항목

```
[문장 레벨]
□ 수동태 → 능동태 ("됐습니다" → "했습니다")
□ 모호한 표현 → 수치/구체 ("개선했습니다" → "2.3s → 0.4s로 줄였습니다")
□ 기술 나열 → 선택 이유 포함
□ 한 문단 = 한 메시지 (여러 메시지가 섞이면 분리)
□ 클리셰 제거: "팀원들과 협력", "최신 기술", "사용자 경험 개선", "효율적인 코드"

[구조 레벨]
□ 1섹션의 첫 문장이 핵심 메시지인가
□ 문제 해결 섹션이 시간순인가
□ 배운 점이 일반론이 아닌 이 프로젝트 특유의 깨달음인가
□ 회고의 "아쉬운 점"이 솔직한가 (자기 홍보만 하면 신뢰도 하락)

[채용담당자 관점]
□ "이 사람이 문제를 스스로 정의했는가" → 문제 섹션에서 확인
□ "왜 그 기술을 골랐는가" → 결정 이유가 보이는가
□ "결과를 어떻게 측정했는가" → 수치 or 측정 필요 명시
□ "실패도 솔직하게 말하는가" → 아쉬운 점, 트레이드오프
```

## 출력

수정된 `data/projects/<slug>.md` (변경 사항 diff 요약 포함)

## 금지

- 사실 추가/변경 금지
- "(측정 필요)" 제거 금지 (수치가 없으면 그대로 유지)
- "(추정)" 제거 금지
