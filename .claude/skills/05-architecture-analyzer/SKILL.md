# 05 · Architecture Analyzer

## 역할

시스템이 어떤 구조로 설계됐는지 파악한다.
컴포넌트 간 관계, 데이터 흐름, 핵심 설계 경계.

## Input

- 01의 폴더 구조
- 02의 기술 스택, 서비스 구조
- 주요 설정 파일 (서비스 포트, 의존성, 빌드 구성)

## Process

```
1. 폴더 구조에서 서비스/레이어 경계 식별
2. 의존성 파일에서 외부 연동 목록 추출
   (DB, 메시지큐, 외부 API, 캐시 등)
3. 서비스 간 통신 방식 추론
   (REST, WebSocket, MQTT, SQS, TCP 등)
4. 핵심 데이터 흐름 1~2개 추적
5. 아키텍처 한 줄 설명 생성
```

## Output → 07-tech-decision-analyzer, 09-portfolio-writer

```
ARCHITECTURE:
- 서비스 구조: (다이어그램 텍스트 or 목록)
- 외부 연동: [...]
- 통신 방식: [...]
- 핵심 데이터 흐름:
  - 흐름 1: A → B → C
  - 흐름 2: ...
- 아키텍처 한 줄 설명:
- 설계 경계 (내가 담당한 컴포넌트 표시):
```

## 주의

- 코드를 보지 않고 구조에서 추론. 추론 시 "(추정)" 표시
- 설계 의도가 불명확하면 질문으로 남기기
