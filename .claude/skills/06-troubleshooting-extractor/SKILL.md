# 06 · Troubleshooting Extractor

## 역할

저장소에서 실제로 겪은 문제들을 발굴한다.
Fix 커밋, 긴 커밋 메시지, hotfix 브랜치, refactor 이유가 단서.

## Input

- 01의 전체 커밋 로그
- 04의 내 커밋 목록

## 발굴 패턴

```
높은 신호:
- "Fix:" 커밋 중 원인 설명이 있는 것
- 커밋 메시지가 50자 이상인 Fix/Bug 커밋
- 동일 파일에 Fix 커밋이 3회 이상 반복
- "hotfix/", "bugfix/" 브랜치
- Refactor 커밋 + 그 직전 Fix 커밋 패턴

낮은 신호 (건너뜀):
- "오타 수정", "merge", "Chore: 설정 변경"
- 커밋 메시지 10자 미만
```

## Process

```
1. 내 커밋에서 Fix/Bug 관련 추출
2. 커밋 메시지 본문에서 원인 언급 추출
3. 반복 수정된 파일/기능 식별 → "어려웠던 것" 후보
4. 각 문제를 "증상 → 원인(추정) → 해결" 구조로 초안 작성
5. 수치가 있으면 반드시 포함, 없으면 "(측정 필요)" 표시
```

## Output → 08-performance-investigator, 09-portfolio-writer

```
TROUBLES:
- 문제 1:
  증상: ...
  커밋 근거: <hash> "커밋 메시지"
  원인: ... (추정)
  해결: ...
  수치: ... or (측정 필요)

- 문제 2: ...
```

## 주의

- 원인이 커밋 메시지에 명시됐으면 인용부호로 직접 인용
- 없는 원인 창작 금지
- 해결 못한 문제는 "미해결" 표시
