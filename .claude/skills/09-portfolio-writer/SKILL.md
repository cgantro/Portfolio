# 09 · Portfolio Writer

## 역할

01~08의 분석 결과를 포트폴리오 서사로 조립한다.
입력 없이 창작하지 말 것 — 항상 앞 스킬의 출력을 원재료로 사용.

## Input

```
필수:
- 02 PROJECT_BRIEF
- 03 TIMELINE
- 04 ROLE
- 06 TROUBLES

선택 (있으면 더 풍부해짐):
- 05 ARCHITECTURE
- 07 TECH_DECISIONS
- 08 PERFORMANCE
```

## 출력 포맷

```md
# <프로젝트명>

## 1. 프로젝트 소개
- 목적:
- 기간: (N주)
- 팀 구성:
- 기술 스택:
- 한 줄 설명:

## 2. 주요 기능 및 역할
[초기] → [중간] → [후반] 단계 서술
내 역할 + 근거 커밋

## 3. 문제 해결 과정
Day X 형식, 최소 3개 항목
문제 → 원인 → 시도 → 해결 → 결과(수치)

## 4. 배운 점
기술적 깨달음 (클리셰 금지)

## 5. 회고
잘한 점 / 아쉬운 점 / 다시 만든다면 / 추가하고 싶은 것
```

## 작성 규칙

- 수동태 금지 ("구현됐습니다" → "직접 설계했습니다")
- 기능 나열 금지 → 문제 해결 스토리
- 수치 없는 결과는 "(측정 필요)" 유지
- 추정 부분 "(추정)" 유지
- 팀원 기여 포함 금지
- 10-portfolio-styler로 넘어갈 초안 품질로 작성

## 출력 위치

`data/projects/<slug>.md`
