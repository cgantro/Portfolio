# 07 · Tech Decision Analyzer

## 역할

"왜 이 기술을 선택했는가"를 재구성한다.
기술 나열이 아니라 선택의 맥락과 트레이드오프를 드러낸다.

## Input

- 02의 기술 스택
- 05의 아키텍처 (외부 연동, 통신 방식)
- 01의 의존성 파일 변경 이력 (기술 교체가 있었으면)

## 발굴 패턴

```
기술 교체 신호:
- 의존성 파일에서 라이브러리 추가/제거 커밋
- "Refactor: X에서 Y로 전환" 패턴 커밋
- "대신", "교체", "migration" 포함 커밋 메시지

선택 이유 신호:
- 커밋 메시지에 "~이유로", "~문제로", "~대신" 포함
- docs/에 설계 결정 문서가 있으면 우선 참조
```

## Process

```
1. 핵심 기술 선택 3~5개 식별 (모든 기술 나열 금지)
2. 각 선택의 "선택한 이유" 추론 (코드/커밋/문서 근거)
3. 포기한 대안이 있으면 명시
4. 선택의 한계 (트레이드오프) 추가
```

## Output → 09-portfolio-writer

```
TECH_DECISIONS:
- 결정 1: <기술명>
  선택 이유: ...
  대안: ... (포기한 이유)
  트레이드오프: ...
  근거: 커밋/문서 참조

- 결정 2: ...
```

## 주의

- "최신 기술이라서", "팀이 익숙해서"는 이유가 아님
- 근거 없으면 "(추론)" 표시 후 기술 특성에서 유추
- 기술 나열 형태로 쓰면 실패
