# 08 · Performance Investigator

## 역할

성능 관련 작업을 집중 분석한다.
수치가 있으면 반드시 추출, 없으면 측정 방법 제안.

## Input

- 01의 커밋 로그
- 06의 TROUBLES (성능 관련 항목)
- 벤치마크/측정 파일 (있으면)

## 발굴 패턴

```
높은 신호:
- 커밋 메시지에 FPS, ms, latency, throughput, 초, % 포함
- "최적화", "개선", "캐싱", "인덱스", "풀" 포함 커밋
- benchmark/, test/ 하위 성능 측정 파일
- *.log, *.csv 벤치마크 결과 파일
- "N배", "N% 향상", "N→M" 패턴

낮은 신호:
- "코드 정리", "리팩토링" (성능 무관)
```

## Process

```
1. 성능 관련 커밋 전체 수집
2. 수치가 포함된 커밋 메시지 우선 추출
3. 벤치마크 파일이 있으면 결과 수치 읽기
4. 개선 전/후 수치 쌍 구성 (없으면 "(측정 필요)" 표시)
5. 성능 개선 스토리: 문제 → 원인 → 접근법 → 결과
```

## Output → 09-portfolio-writer

```
PERFORMANCE:
- 항목 1: <무엇을 개선>
  문제: (수치 포함)
  원인:
  접근법:
  결과: N → M (단위)
  근거: 커밋/파일

- 항목 2: ...
- 수치 없는 항목: (측정 필요)
```

## 주의

- 수치는 출처(커밋 메시지, 파일명) 명시
- "성능을 개선했습니다"만 있고 수치 없으면 "(측정 필요)" 표시
- Debug 빌드 vs Release 빌드 구분 있으면 명시
