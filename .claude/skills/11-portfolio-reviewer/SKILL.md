# 11 · Portfolio Reviewer

## 역할

완성된 포트폴리오 항목을 최종 검수한다.
통과/수정 필요/차단 3단계로 분류한다.

## Input

- 10-portfolio-styler 출력 (`data/projects/<slug>.md`)

## 검수 기준

```
[차단] — 이대로 제출 불가
- 팀원 기여가 내 것으로 서술됨
- 없는 수치를 창작했음
- 추정 내용에 "(추정)" 표시 없음
- 문제 해결 섹션이 3개 미만
- 기술 나열만 있고 선택 이유/결과 없음

[수정 필요] — 보완하면 제출 가능
- 수치가 하나도 없음 (측정 필요 항목만 있어도 허용)
- 배운 점이 클리셰 ("협업의 중요성을 배웠습니다")
- 회고에 아쉬운 점이 없음
- "한 일" 위주, "왜 했는가"가 없음
- 프로젝트 한 줄 설명이 기능 나열

[통과] — 제출 가능
- 위 항목 해당 없음
- 채용담당자가 3가지를 확인할 수 있음:
  1. 문제를 스스로 정의했는가
  2. 선택의 이유가 있는가
  3. 결과를 측정하려 했는가
```

## 출력 포맷

```
## Review: <slug>

### [차단]
- (없으면 "없음")

### [수정 필요]
- 항목: ...
  제안: ...

### [통과]
- 잘 된 부분: ...

### 최종 판정: 차단 / 수정 후 제출 / 제출 가능
```

## 이후

- [차단]: 10-portfolio-styler로 돌아가서 수정
- [수정 필요]: 수정 사항 반영 후 재검수 (선택)
- [통과]: `data/projects/<slug>.md` 최종 확정
